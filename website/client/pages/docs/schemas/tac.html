Schemas & migrations

Schemas are optional, versioned, and enforced by the chex binary. Old documents are not rewritten when the schema moves forward — they are materialized to the head shape in memory as they are read, by upgrader functions you write.

Layout

Schemas live under FYLO_SCHEMA, one directory per collection. Any directory there containing a manifest.json is auto-created as a collection when the database opens. 

{layoutCode}
{manifestCode}

Schemas are chex regex schemas — a field name mapped to a pattern the value must match. A trailing ? on a field name makes it optional. 

{schemaCode}

Upgraders

An upgrader is a pure function from one version's document shape to the next. FYLO chains them on read, so a v1 document written two years ago is returned in v3 shape without ever being rewritten on disk. 

{upgraderCode}

Behaviour

  • Documents carry _v, their version label.
  • Reads materialize old documents to head shape in memory.
  • Strict writes validate against the head schema via the chex binary.
  • A document missing _v is treated as the oldest version and upgraded on read.
  • Mutation and query methods await schema bootstrap internally. If you need it settled before a synchronous probe, await fylo.ready().

No arrays of objects

FYLO schemas do not support arrays of objects — declare each nested object as its own collection. A schema that would accept items as a list of records throws on first read, naming the offending path. Arrays of scalars and nested objects used as fields are fine.

This is the same rule the storage layer enforces at write time with EARRAYOFOBJECTS; the schema layer simply refuses to promise something the data model will reject. See Documents & metadata.

Strict mode

Set FYLO_STRICT to validate every document against the head schema before it is written. Without it, schemas still drive read-time upgrades and encryption registration but do not gate writes. 

{cliCode}

schema doctor is the readiness check: it reports a manifest that disagrees with the files on disk, a missing upgrader in the chain, or a schema that the data model cannot accept.

Schemas drive encryption

The $encrypted array in a schema is what tells FYLO which fields to encrypt and, just as importantly, which fields must be decryptable on read. That registration is loaded on first read, so a read-only replica decrypts correctly without ever writing. See Encryption & access.
