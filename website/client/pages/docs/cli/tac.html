CLI

The same engine your application drives, with a human at the keyboard. Every command takes --root (or reads FYLO_ROOT), and most take --json for machine-readable output and scriptable exit codes.

Version control

{vcsCode}

status and diff compare document payloads only, so rebuilt indexes and mtime-only changes never show up as noise. restore-commit refuses to overwrite uncommitted changes without --force.

Filesystem snapshot and restore

{recoveryCode}

FYLO has no built-in object-storage client. Snapshot tooling must preserve native metadata, and restore always targets a new directory rather than merging into a live root. The full runbook is on Backup & sync.

Machine mode

fylo exec is the interface every non-JavaScript client uses. It reads one JSON request and writes one JSON response, or holds a persistent NDJSON loop. 

{execCode}

The framing contract, cursor rules, and the exclusive root lease are documented on Machine protocol.

Identity

{versionCode}

version --output json and the handshake operation share one stable identity payload: FYLO runtime and protocol versions, the immutable release commit and build target, required CHEX and TTID versions plus their current availability, effective frame limits, and supported capabilities. Source and locally compiled builds report an unknown commit; release builds embed the exact source revision.
