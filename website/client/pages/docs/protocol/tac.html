Machine protocol

One JSON object in, one JSON object out. This is the canonical surface — every language client is a thin wrapper over it, and anything a client can do, you can do from a shell. No client invents behaviour the protocol does not have.

Every response carries protocolVersion, ok, the op it answered, and durationMs. A successful response carries result; a failed one carries error with a non-empty code.

Handshake first

Before sending ordinary operations, a supervisor can identify the exact runtime and discover its framing contract. A handshake is side-effect-free: it does not create the configured root or initialize a collection. 

{handshakeCode}

It reports FYLO runtime and protocol versions, the immutable release commit and build target, required CHEX and TTID versions with their current availability, effective frame limits, and supported capabilities. Branch on capabilities, not on a version string.

Capability records are versioned contracts. documentBuckets.version === 1 identifies raw-file collection support and lists the operations, input forms, and integrity level implemented by this runtime. On macOS and Linux, machineAccess.version === 1 lists the operations and denial semantics covered by trusted POSTIX access. Its absence means the build does not provide that authorization boundary. Reject a missing or unknown capability version before touching a production root.

An operation this runtime does not know returns EUNSUPPORTEDOP — the set is additive across releases, so check the handshake rather than assuming.

Access context

Document and raw-file CRUD and query operations accept an optional access object. Puts accept a UID, GID, and mode; reads, metadata, queries, updates, deletes, and restores accept a UID. A trusted binary-backed application may additionally include groups for virtual POSIX membership. 

{accessCode}

Denied direct operations return EACCES; collection queries omit unreadable records instead of failing. See Encryption & access for the trust boundary this assumes.

Bounded NDJSON frames

Persistent loops use one UTF-8 JSON object per LF-delimited line. The secure defaults are 1 MiB per request and 8 MiB per response; the delimiter does not count. A supervisor may lower or raise them, up to 64 MiB, then confirm the effective values in the handshake. 

{framesCode}

FYLO uses a fixed-capacity input buffer. It rejects invalid UTF-8 (EFRAME_UTF8), malformed JSON (EFRAME_JSON), duplicate object keys (EFRAME_DUPLICATE_KEY), and oversized requests (EFRAME_REQUEST_TOO_LARGE). When an LF boundary is known it emits one error response and safely resumes with the next frame. An incomplete final frame returns EFRAME_TRUNCATED at EOF and the loop ends — retry it only after starting a new child.

Responses never silently cross the advertised maximum. If a client observes an oversized or malformed response despite the negotiated contract, it must kill and restart the child, because the framing can no longer be trusted.

Pagination

findDocs and findDeletedDocs support bounded continuation on a persistent loop. 

{pageCode}

The result is items, nextCursor, and page. The first request materializes an immutable, process-scoped snapshot ordered by TTID binary text, so concurrent mutations cannot duplicate or skip entries. Cursors are scoped to the operation, collection, query, and access identity; they expire after 15 minutes and become invalid when the loop exits.

Unpaged operations that exceed the frame return EFRAME_RESPONSE_TOO_LARGE while preserving stream synchronization. A single item that cannot fit returns EQUERYITEMTOOLARGE; an oversized snapshot returns EQUERYSNAPSHOTTOOLARGE. Snapshot state is private to the native process, cleaned on completion, expiry, or shutdown, and capped at 1 GiB.

Exclusive root owner

Long-lived supervisors that require exactly one authoritative process can take a root-wide lease. 

{leaseCode}

FYLO canonicalizes the root, acquires a non-blocking kernel file lock before it reads stdin, and holds it for the whole loop lifetime. A competing process receives EROOTLOCKED and exits without executing a read or write. Normal shutdown releases the lock; after a crash or SIGKILL the operating system does. Persistent metadata is diagnostic and fencing state, not a PID-file claim, so PID reuse and stale metadata cannot retain ownership. Every request verifies the unique owner generation, and a replaced former owner fails closed with EROOTLEASELOST.

The lease is a kernel lock, not a distributed lock service. It is supported on native local filesystems on macOS, Linux, and Windows. Containers on one host can share it only when they share the same canonical bind-mounted root and host kernel lock domain. Network, clustered, object-backed, and independently synchronized filesystems — including Windows UNC shares — are unsupported; use an external lease or consensus service there.

Interop

The compiled executable's interop contract is tested in CI against Python, Ruby, PHP, Dart, Java, C#, C++, Swift, Kotlin, and Rust. Each language invokes the same fylo exec protocol, so non-JavaScript callers never depend on JS-only conveniences such as the sql template tag or the db.<collection> facade.
