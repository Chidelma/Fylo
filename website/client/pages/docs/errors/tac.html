Error codes

Every failed machine response carries a non-empty error.code. The set is additive — new codes may appear in later releases, and an existing code keeps its meaning forever. Branch on the code, never on the message text.

Storage-level codes

Failures raised below the protocol layer may carry additional stable codes — for example FYLO_COLLECTION_NOT_FOUND. Those retain their meaning across releases under the same additive policy, so they are equally safe to branch on.

In-process errors

The Node and browser APIs throw typed errors rather than returning a response envelope. A denied operation throws FyloPermissionError with code === 'EACCES'; the code values are the same set documented above, so error handling ports between the two surfaces without a translation table.
