Native shims stay thin

Native clients spawn fylo exec --loop, negotiate capabilities with a handshake, and map stable error codes into language-native exceptions. Copy the version-matched client file from the release archive; there is no package registry or linked storage implementation to keep in sync.

See Machine protocol for framing and pagination, or Browser & Explorer for the local OPFS and File System Access adapters.

Scope environment to one FYLO child

Every binary-backed SDK shim accepts an optional child environment. Point it at a .env file or pass the language's native map or dictionary. File and map values override inherited variables for that child without changing the host process.

The same file can be used by every native shim:

# ./config/fylo.env
export FYLO_SCHEMA="/srv/app/schemas"
FYLO_STRICT=1
FYLO_SHARD_WIDTH=2

A missing or malformed file fails before FYLO starts. The loader supports comments, an optional export prefix, and quoted values; it deliberately does not execute substitutions or mutate the host environment. The same setting is available in the Python, Ruby, PHP, Go, Rust, Java, C#, and Dart shims. Browser and mobile clients configure their storage adapters directly because they do not launch a FYLO child process.

Relative .env paths resolve from the application process's working directory. Keep files containing encryption credentials out of source control and restrict their filesystem permissions.

Treat both the file path and map as trusted bootstrap configuration. Never take either from a request, tenant setting, upload, or job payload: arbitrary keys can alter PATH, dynamic-loader behavior, and the child program. Use an absolute, administrator-controlled binary path, allowlist supported FYLO_* keys, copy inherited values explicitly, and prefer a secret manager or owner-only files (for example, chmod 600).
